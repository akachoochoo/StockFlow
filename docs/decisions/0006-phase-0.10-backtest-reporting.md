```
Backtest Reporting Enhancement: Drawdown Episode Analysis with Strategy-Agnostic Trade Markers

## Context
Phase 0.9가 종료된 시점에서, 백테스트 결과 진단 역량을 강화하고자 한다.
현재 백테스트는 집계 지표(MDD, Sharpe, CAGR 등)는 산출하지만, **"왜 그
손실이 발생했는가"를 시각적·구조적으로 진단하는 도구가 없다.** 향후 KIS
API 라이브 트레이딩 전, 그리고 다중 전략 운용을 앞두고 이 갭을 메운다.

또한 본 시스템은 세븐 스플릿 외에 다른 매매 기법(예: MA 크로스, RSI,
모멘텀 등)도 수용해야 하므로, **리포팅 레이어는 특정 전략에 결합되지
않아야 한다.**

## Goals
1. 백테스트 결과에서 의미 있는 손실 구간(drawdown episode)을 자동 탐지
2. 각 episode별로 캔들차트 + 매매 마커(B/S) + 진단 패널을 포함한 리포트 생성
3. 전략-무관(strategy-agnostic) 설계로, 신규 전략 추가 시 리포팅 모듈을
   수정하지 않아도 동작

## Non-Goals
- 실시간 모니터링 대시보드 (별도 페이즈)
- 라이브 트레이딩 알람 연동 (KIS API 통합 이후)
- 전략 자체의 변경 및 튜닝

(생략 — 사용자 spec 전체 박제는 본 ADR §1.2 ~ §11 본문 참조)
```

## 3. ADR-1: Trade view model — 도메인 엔티티 도입 zero, view model 채택

### 3.0 사용자 spec 의 의도

```python
@dataclass(frozen=True)
class Trade:
    timestamp: datetime
    symbol: str
    side: Literal["BUY", "SELL"]
    price: Decimal
    quantity: Decimal
    strategy_id: str
    annotations: Mapping[str, Any]
```

세븐 스플릿: `{"split_no": 3, "split_total": 7, "trigger_price": ...}`
MA 크로스: `{"signal": "golden_cross", "fast": 20, "slow": 60}`
RSI: `{"rsi": 28.3, "threshold": 30}`

### 3.1 현재 구조 검토

`src/domain/models.py` 기존 모델:

| 모델 | 역할 | strategy 메타데이터 |
|---|---|---|
| `Decision` | 1 일치 의사결정 aggregate | `reasoning: dict[str, str]` (top-level) |
| `BuyActionRecord` | 1 매수 | `reasoning: dict[str, str]` ✓ |
| `SellActionRecord` | 1 매도 | `reasoning: dict[str, str]` ✓ |
| `Order` | 영구 주문 (DB) | strategy 메타 없음 |

**핵심 발견**: `BuyActionRecord` / `SellActionRecord` 가 이미 사용자
spec 의 `annotations` 와 동등한 strategy 별 자유 메타데이터 dict 보유.
+ `Decision.timestamp` (UTC) + `Decision.asset.code` (symbol) 조합으로
사용자 spec 의 `Trade` 와 1:1 매핑 가능.

### 3.2 결정 — 도메인 엔티티 도입 zero, application view model 도입

| 옵션 | 채택 | 근거 |
|---|---|---|
| A) 신규 `Trade` 도메인 엔티티 도입 (사용자 spec 그대로) | **거부** | 기존 `Decision` + `BuyActionRecord` / `SellActionRecord` 와 정보 중복. 영구화 추가 부담. CLAUDE.md "친절한 추가 금지" 정신 |
| **B) Application layer view model `TradeView` (dataclass) — 기존 모델에서 lazy 변환** | **채택** | 기존 모델 변경 zero, 신규 도메인 엔티티 zero. 리포팅 layer 만 view model 사용. 영구화 zero (백테스트 실행 시 in-memory) |
| C) 기존 `BuyActionRecord` / `SellActionRecord` 에 `timestamp` / `side` / `strategy_name` 추가 | 거부 | Decision 의 timestamp 와 중복 + 기존 schema 변경 → 마이그레이션 부담. Phase 1+ 다중 전략 시점에 재검토 |

### 3.3 ADR-1 박제 — `TradeView` view model

위치: `src/application/reporting/trade_view.py` (신규)

```python
from __future__ import annotations
from dataclasses import dataclass
from datetime import datetime
from decimal import Decimal
from typing import Any, Literal

from src.domain.models import Decision


@dataclass(frozen=True)
class TradeView:
    """리포팅 layer view model — Decision/BuyActionRecord/SellActionRecord
    에서 변환한 incoming 분석용 dto.

    domain 엔티티 아님 (영구화 X). lazy 변환 함수 ``trades_from_decisions``
    가 BacktestResult.decisions 를 iterate 하여 TradeView list 생성.
    """
    timestamp: datetime  # UTC (Decision.timestamp)
    symbol: str  # asset.code
    side: Literal["BUY", "SELL"]
    price: Decimal  # filled_price
    quantity: Decimal  # filled_quantity
    strategy_id: str  # Phase 0.10: yaml buy_strategy field
    annotations: dict[str, Any]  # reasoning dict (str→Any 자유 변환)


def trades_from_decisions(
    decisions: list[Decision],
    strategy_id: str,
) -> list[TradeView]:
    """BacktestResult.decisions → TradeView list.

    Phase 0.10: single-strategy assumption (BacktestResult 가 single
    buy_strategy_name 보유). 다중 전략 운용 시점에 strategy 식별을
    BuyActionRecord/SellActionRecord 자체로 이동 검토 (Phase 1+ ADR).
    """
    out: list[TradeView] = []
    for d in decisions:
        if d.buy_action is not None:
            out.append(TradeView(
                timestamp=d.timestamp,
                symbol=d.asset.code,
                side="BUY",
                price=d.buy_action.filled_price,
                quantity=d.buy_action.filled_quantity,
                strategy_id=strategy_id,
                annotations=dict(d.buy_action.reasoning),
            ))
        for sa in d.sell_actions:
            out.append(TradeView(
                timestamp=d.timestamp,
                symbol=d.asset.code,
                side="SELL",
                price=sa.filled_price,
                quantity=sa.filled_quantity,
                strategy_id=strategy_id,
                annotations=dict(sa.reasoning),
            ))
    return out
```

### 3.4 strategy_id 매핑 (Phase 0.10 single-strategy)

Phase 0.10 = single-strategy assumption (yaml `buy_strategy:
"price_drop"` 또는 `"support_level"` 단일 값). `BacktestRunner` 가 이미
`buy_strategy_name` 보유 → 변환 시 인자로 전달.

다중 전략 운용 (Phase 1+) 시점:
- `BuyActionRecord` / `SellActionRecord` 에 `strategy_name` field 추가
  (스키마 마이그레이션)
- 또는 `Decision.reasoning["strategy_name"]` 로 영구화 (스키마 변경 zero)
- 결정 보류 — Phase 1 ADR 0007 박제 시점

### 3.5 영구화 정책

`TradeView` = view model only (in-memory). 영구화 zero. 백테스트 결과
영구화는 기존 `Decision` / `Order` repository (Phase 0~0.9 박제) 그대로.

### 3.6 ADR-1 후속 작업 (Step A)

- Step A.1: `src/application/reporting/__init__.py` + `trade_view.py` 신규
- Step A.2: `tests/unit/test_trade_view.py` — 변환 + 보호 invariant
  (price > 0 / quantity > 0 / Literal 검증)

from __future__ import annotations
from collections.abc import Sequence
from dataclasses import dataclass
from typing import Protocol, runtime_checkable

from src.application.reporting.trade_view import TradeView
from src.application.reporting.episode import DrawdownEpisode


@dataclass(frozen=True)
class MarkerStyle:
    """차트 마커 시각 속성 — 차트 라이브러리 무관 spec."""
    color: str  # CSS hex or name (예: "#1f77b4")
    marker: str  # mplfinance marker code (예: "^" "v" "o" "s")
    size: int  # pt
    label: str  # 차트 위 표기 (예: "B1" "S3")

    """리포트 진단 패널 — HTML 출력 무관 dataclass."""

class StrategyRenderer(Protocol):

    코어 리포팅 모듈 (`src/application/reporting/`) 은 본 Protocol 만
    의존. 구현체는 `src/adapters/reporting/renderers/` 에 위치.
    Registry 가 `strategy_id → renderer` mapping 보유.
    """

    def marker_label(self, trade: TradeView) -> str: ...
    def marker_style(self, trade: TradeView) -> MarkerStyle: ...
    def diagnostic_panels(
        self,
        trades: Sequence[TradeView],
        episode: "DrawdownEpisode",
    ) -> Sequence[Panel]: ...
```

class SevenSplitRenderer:
    """세븐 스플릿 (PriceDropStrategy / SupportLevelStrategy) 차수 표기.

    Annotation key 매핑:
    - BUY:  ``split_number`` (BuyActionRecord.reasoning 에 포함)
            또는 ``split_level_after`` fallback

            또는 reasoning 의 추가 ``profit_pct`` 활용

    SPLIT_COLORS = {
        1: "#1f77b4", 2: "#ff7f0e", 3: "#2ca02c", 4: "#d62728",
        5: "#9467bd", 6: "#8c564b", 7: "#7f7f7f",
    }

    def marker_label(self, trade: TradeView) -> str:
        n = self._slot(trade)
        return f"B{n}" if trade.side == "BUY" else f"S{n}"

    def marker_style(self, trade: TradeView) -> MarkerStyle:
        n = self._slot(trade)
        return MarkerStyle(
            color=self.SPLIT_COLORS.get(n, "#000000"),
            marker="^" if trade.side == "BUY" else "v",
            size=10,
            label=self.marker_label(trade),
        )

    def diagnostic_panels(self, trades, episode) -> Sequence[Panel]:
        # Episode 구간 내 차수별 buy/sell 횟수 + lock-in (split_level=7)
        # 비율 + 평균 entry price 등
        ...

    def _slot(self, trade: TradeView) -> int:
        key = "split_number" if trade.side == "BUY" else "slot_number"
        return int(trade.annotations.get(key, 0))
```

### 4.4 Registry

위치: `src/adapters/reporting/renderer_registry.py` (신규)

```python
from src.ports.strategy_renderer import StrategyRenderer
from src.adapters.reporting.renderers.seven_split import SevenSplitRenderer
from src.adapters.reporting.renderers.default import DefaultRenderer


class StrategyRendererRegistry:
    """strategy_id → renderer mapping. 정적 dict 기반 (Phase 0.10).

    동적 plugin discovery (entry points 등) 는 Phase 0.11+ 검토.
    """

    def __init__(self) -> None:
        self._renderers: dict[str, StrategyRenderer] = {
            "price_drop": SevenSplitRenderer(),
            "support_level": SevenSplitRenderer(),  # SupportSlot 동일 매핑
        }
        self._default: StrategyRenderer = DefaultRenderer()

    def get(self, strategy_id: str) -> StrategyRenderer:
        """Lookup. 미등록 strategy 는 DefaultRenderer 반환 (Acceptance
        Criteria 3 — 신규 dummy strategy 추가 시 코어 변경 zero)."""
        return self._renderers.get(strategy_id, self._default)

    def register(
        self, strategy_id: str, renderer: StrategyRenderer,
    ) -> None:
        """런타임 등록 — 외부 plugin 또는 테스트용."""
        self._renderers[strategy_id] = renderer
```

## 5. ADR-3: DrawdownEpisodeDetector — 전략 무관 분석 모듈

### 5.0 사용자 spec 의 의도

> equity curve 만 입력받아 동작. 임계치 (예: -5%) 이상 peak-to-trough
> 구간을 episode 로 추출. Episode 메타: 시작 / 저점 / 회복 시점, MDD%,
> duration, 회복 여부.

### 5.1 결정 — Application layer 의 strategy-agnostic 분석 모듈

| 옵션 | 채택 | 근거 |
|---|---|---|
| **A) `src/application/reporting/episode.py` (DrawdownEpisode dataclass + detector)** | **채택** | strategy-agnostic. Equity curve (BacktestResult.snapshots → total_value series) 만 입력 |
| B) Domain layer 추가 | 거부 | Domain 의 본질 (의사결정 + 잔고) 외 분석 — application 적합 |

### 5.2 DrawdownEpisode dataclass

위치: `src/application/reporting/episode.py` (신규)

```python
from __future__ import annotations
from dataclasses import dataclass
from datetime import date
from decimal import Decimal


@dataclass(frozen=True)
class DrawdownEpisode:
    """Equity curve 의 1 개 drawdown episode.

    peak_date → trough_date 손실 구간 + recovery_date (옵션, peak 회복
    시점). 회복 안 된 경우 ``recovered=False`` / ``recovery_date=None``.
    """
    peak_date: date
    peak_value: Decimal
    trough_date: date
    trough_value: Decimal
    recovery_date: date | None
    recovered: bool
    drawdown_pct: Decimal  # negative (예: Decimal("-22.6639"))
    duration_days: int  # peak_date 부터 recovery_date (또는 series end)
    asset_code: str | None = None  # None = portfolio level, else asset code
```

### 5.3 Detector

```python
from collections.abc import Sequence


def detect_drawdown_episodes(
    equity_curve: Sequence[tuple[date, Decimal]],
    threshold_pct: Decimal = Decimal("-5"),
    *,
    asset_code: str | None = None,
) -> list[DrawdownEpisode]:
    """Equity curve 에서 |drawdown| ≥ |threshold_pct| 인 episode 추출.

    Algorithm:
    1. running peak_value (peak_date) 추적
    2. 각 (date, value) 에서 drawdown = (value - peak_value) / peak_value * 100
    3. drawdown ≤ threshold_pct (예: -5%) 진입 시 episode 시작 (peak 박제)
    4. trough = episode 내 minimum value
    5. value ≥ peak_value 회복 시 episode 종료 (recovered=True,
       recovery_date 박제)
    6. 마지막 episode 회복 안 된 경우 recovered=False,
       recovery_date=None, duration = series_end - peak_date

    Args:
        equity_curve: (date, value) sorted ascending by date.
        threshold_pct: 음수 (예: Decimal("-5") for -5%).
        asset_code: portfolio level = None, asset level = code.

    Returns:
        List of episodes ordered by peak_date.
    """
    ...  # 구현은 Step A.3 sub-step
```

### 5.4 임계치 정책 — Open Question Q1 답변

| 옵션 | 채택 | 근거 |
|---|---|---|
| **A) `-5%` 기본 + yaml/CLI 설정 가능** | **채택** | Phase 0.7.3 MDD -8.27% / Phase 0.9.1 -22.66% / Phase 0.9.2 -37.65% 모두에서 다수 episode 추출 가능 |
| B) `-10%` 기본 | 거부 | Phase 0.7.3 의 -8.27% MDD 가 episode 0 개 → 분석 불가 |
| C) `-3%` 기본 | 거부 | noise 가능성 (단기 fluctuation) |

→ default `-5.0%`. yaml `reporting.drawdown_threshold_pct` 또는 CLI
`--threshold` 로 override 가능.

### 5.5 멀티 자산 episode 정의 — Open Question Q4 답변

| 옵션 | 채택 | 근거 |
|---|---|---|
| **A) Portfolio level (default) + asset level (옵션) + both** | **채택** | Portfolio = 전체 손실 진단 (사용자 의도). Asset = 종목별 lock-in 진단 (Phase 0.9 발견 패턴 — 005930/015760/097950 split_level=7). 양쪽 모두 가치 |
| B) Portfolio only | 거부 | Phase 0.9 의 종목별 lock-in 진단 불가 |
| C) Asset only | 거부 | "전체 손실 진단" 본질 약화 |

→ CLI `--episode-scope portfolio | asset | both` (default `portfolio`).
yaml 설정 가능.

- Portfolio scope = `BacktestResult.snapshots[i].total_value` series
- Asset scope = `BacktestResult.snapshots[i].valuations[j].market_value`
  series (per-asset)
- Both = 둘 다 추출, HTML index 에 분리 표기

### 5.6 Episode 회복 판정

`recovered=True` 조건: episode 내 어느 시점에 `value >= peak_value` 도달.
`recovery_date` = 첫 회복 시점.

마지막 episode 가 recovery 안 된 경우 (예: Phase 0.9.1 의 -22.66% MDD
가 백테스트 종료 시점에도 회복 안 됨) `recovered=False`,
`recovery_date=None`, `duration_days = series_end - peak_date`.

  - Single peak-trough-recovery cycle
