```
Backtest Reporting Enhancement: Drawdown Episode Analysis with Strategy-Agnostic Trade Markers

## Context
Phase 0.9가 종료된 시점에서, 백테스트 결과 진단 역량을 강화하고자 한다.
현재 백테스트는 집계 지표(MDD, Sharpe, CAGR 등)는 산출하지만, **"왜 그
손실이 발생했는가"를 시각적·구조적으로 진단하는 도구가 없다.** 향후 KIS
API 라이브 트레이딩 전, 그리고 다중 전략 운용을 앞두고 이 갭을 메운다.

또한 본 시스템은 세븐 스플릿 외에 다른 매매 기법(예: MA 크로스, RSI,
모멘텀 등)도 수용해야 하므로, **리포팅 레이어는 특정 전략에 결합되지
않아야 한다.**

## Goals
1. 백테스트 결과에서 의미 있는 손실 구간(drawdown episode)을 자동 탐지
2. 각 episode별로 캔들차트 + 매매 마커(B/S) + 진단 패널을 포함한 리포트 생성
3. 전략-무관(strategy-agnostic) 설계로, 신규 전략 추가 시 리포팅 모듈을
   수정하지 않아도 동작

## Non-Goals
- 실시간 모니터링 대시보드 (별도 페이즈)
- 라이브 트레이딩 알람 연동 (KIS API 통합 이후)
- 전략 자체의 변경 및 튜닝

(생략 — 사용자 spec 전체 박제는 본 ADR §1.2 ~ §11 본문 참조)
```

## 3. ADR-1: Trade view model — 도메인 엔티티 도입 zero, view model 채택

### 3.0 사용자 spec 의 의도

```python
@dataclass(frozen=True)
class Trade:
    timestamp: datetime
    symbol: str
    side: Literal["BUY", "SELL"]
    price: Decimal
    quantity: Decimal
    strategy_id: str
    annotations: Mapping[str, Any]
```

세븐 스플릿: `{"split_no": 3, "split_total": 7, "trigger_price": ...}`
MA 크로스: `{"signal": "golden_cross", "fast": 20, "slow": 60}`
RSI: `{"rsi": 28.3, "threshold": 30}`

### 3.1 현재 구조 검토

`src/domain/models.py` 기존 모델:

| 모델 | 역할 | strategy 메타데이터 |
|---|---|---|
| `Decision` | 1 일치 의사결정 aggregate | `reasoning: dict[str, str]` (top-level) |
| `BuyActionRecord` | 1 매수 | `reasoning: dict[str, str]` ✓ |
| `SellActionRecord` | 1 매도 | `reasoning: dict[str, str]` ✓ |
| `Order` | 영구 주문 (DB) | strategy 메타 없음 |

**핵심 발견**: `BuyActionRecord` / `SellActionRecord` 가 이미 사용자
spec 의 `annotations` 와 동등한 strategy 별 자유 메타데이터 dict 보유.
+ `Decision.timestamp` (UTC) + `Decision.asset.code` (symbol) 조합으로
사용자 spec 의 `Trade` 와 1:1 매핑 가능.

### 3.2 결정 — 도메인 엔티티 도입 zero, application view model 도입

| 옵션 | 채택 | 근거 |
|---|---|---|
| A) 신규 `Trade` 도메인 엔티티 도입 (사용자 spec 그대로) | **거부** | 기존 `Decision` + `BuyActionRecord` / `SellActionRecord` 와 정보 중복. 영구화 추가 부담. CLAUDE.md "친절한 추가 금지" 정신 |
| **B) Application layer view model `TradeView` (dataclass) — 기존 모델에서 lazy 변환** | **채택** | 기존 모델 변경 zero, 신규 도메인 엔티티 zero. 리포팅 layer 만 view model 사용. 영구화 zero (백테스트 실행 시 in-memory) |
| C) 기존 `BuyActionRecord` / `SellActionRecord` 에 `timestamp` / `side` / `strategy_name` 추가 | 거부 | Decision 의 timestamp 와 중복 + 기존 schema 변경 → 마이그레이션 부담. Phase 1+ 다중 전략 시점에 재검토 |

### 3.3 ADR-1 박제 — `TradeView` view model

위치: `src/application/reporting/trade_view.py` (신규)

```python
from __future__ import annotations
from dataclasses import dataclass
from datetime import datetime
from decimal import Decimal
from typing import Any, Literal

from src.domain.models import Decision


@dataclass(frozen=True)
class TradeView:
    """리포팅 layer view model — Decision/BuyActionRecord/SellActionRecord
    에서 변환한 incoming 분석용 dto.

    domain 엔티티 아님 (영구화 X). lazy 변환 함수 ``trades_from_decisions``
    가 BacktestResult.decisions 를 iterate 하여 TradeView list 생성.
    """
    timestamp: datetime  # UTC (Decision.timestamp)
    symbol: str  # asset.code
    side: Literal["BUY", "SELL"]
    price: Decimal  # filled_price
    quantity: Decimal  # filled_quantity
    strategy_id: str  # Phase 0.10: yaml buy_strategy field
    annotations: dict[str, Any]  # reasoning dict (str→Any 자유 변환)


def trades_from_decisions(
    decisions: list[Decision],
    strategy_id: str,
) -> list[TradeView]:
    """BacktestResult.decisions → TradeView list.

    Phase 0.10: single-strategy assumption (BacktestResult 가 single
    buy_strategy_name 보유). 다중 전략 운용 시점에 strategy 식별을
    BuyActionRecord/SellActionRecord 자체로 이동 검토 (Phase 1+ ADR).
    """
    out: list[TradeView] = []
    for d in decisions:
        if d.buy_action is not None:
            out.append(TradeView(
                timestamp=d.timestamp,
                symbol=d.asset.code,
                side="BUY",
                price=d.buy_action.filled_price,
                quantity=d.buy_action.filled_quantity,
                strategy_id=strategy_id,
                annotations=dict(d.buy_action.reasoning),
            ))
        for sa in d.sell_actions:
            out.append(TradeView(
                timestamp=d.timestamp,
                symbol=d.asset.code,
                side="SELL",
                price=sa.filled_price,
                quantity=sa.filled_quantity,
                strategy_id=strategy_id,
                annotations=dict(sa.reasoning),
            ))
    return out
```

### 3.4 strategy_id 매핑 (Phase 0.10 single-strategy)

Phase 0.10 = single-strategy assumption (yaml `buy_strategy:
"price_drop"` 또는 `"support_level"` 단일 값). `BacktestRunner` 가 이미
`buy_strategy_name` 보유 → 변환 시 인자로 전달.

다중 전략 운용 (Phase 1+) 시점:
- `BuyActionRecord` / `SellActionRecord` 에 `strategy_name` field 추가
  (스키마 마이그레이션)
- 또는 `Decision.reasoning["strategy_name"]` 로 영구화 (스키마 변경 zero)
- 결정 보류 — Phase 1 ADR 0007 박제 시점

### 3.5 영구화 정책

`TradeView` = view model only (in-memory). 영구화 zero. 백테스트 결과
영구화는 기존 `Decision` / `Order` repository (Phase 0~0.9 박제) 그대로.

### 3.6 ADR-1 후속 작업 (Step A)

- Step A.1: `src/application/reporting/__init__.py` + `trade_view.py` 신규
- Step A.2: `tests/unit/test_trade_view.py` — 변환 + 보호 invariant
  (price > 0 / quantity > 0 / Literal 검증)

```python
from __future__ import annotations
from collections.abc import Sequence
from dataclasses import dataclass
from typing import Protocol, runtime_checkable

from src.application.reporting.trade_view import TradeView
from src.application.reporting.episode import DrawdownEpisode


@dataclass(frozen=True)
class MarkerStyle:
    """차트 마커 시각 속성 — 차트 라이브러리 무관 spec."""
    color: str  # CSS hex or name (예: "#1f77b4")

    size: int  # pt

    의존. 구현체는 `src/adapters/reporting/renderers/` 에 위치.
    Registry 가 `strategy_id → renderer` mapping 보유.

    def marker_label(self, trade: TradeView) -> str: ...
    def marker_style(self, trade: TradeView) -> MarkerStyle: ...
    def diagnostic_panels(
        self,
        trades: Sequence[TradeView],
        episode: "DrawdownEpisode",
    ) -> Sequence[Panel]: ...
```

```python
    Annotation key 매핑:
    - BUY:  ``split_number`` (BuyActionRecord.reasoning 에 포함)
            또는 ``split_level_after`` fallback

            또는 reasoning 의 추가 ``profit_pct`` 활용

    SPLIT_COLORS = {
        1: "#1f77b4", 2: "#ff7f0e", 3: "#2ca02c", 4: "#d62728",
        5: "#9467bd", 6: "#8c564b", 7: "#7f7f7f",
    }

    def marker_label(self, trade: TradeView) -> str:
        n = self._slot(trade)
        return f"B{n}" if trade.side == "BUY" else f"S{n}"

    def marker_style(self, trade: TradeView) -> MarkerStyle:
        n = self._slot(trade)
        return MarkerStyle(
            color=self.SPLIT_COLORS.get(n, "#000000"),
            marker="^" if trade.side == "BUY" else "v",
            size=10,
            label=self.marker_label(trade),
        )

    def diagnostic_panels(self, trades, episode) -> Sequence[Panel]:
        # Episode 구간 내 차수별 buy/sell 횟수 + lock-in (split_level=7)
        # 비율 + 평균 entry price 등
        ...

    def _slot(self, trade: TradeView) -> int:
        key = "split_number" if trade.side == "BUY" else "slot_number"
        return int(trade.annotations.get(key, 0))
```

### 4.4 Registry

위치: `src/adapters/reporting/renderer_registry.py` (신규)

```python
from src.ports.strategy_renderer import StrategyRenderer
from src.adapters.reporting.renderers.seven_split import SevenSplitRenderer
from src.adapters.reporting.renderers.default import DefaultRenderer


class StrategyRendererRegistry:
    """strategy_id → renderer mapping. 정적 dict 기반 (Phase 0.10).

    동적 plugin discovery (entry points 등) 는 Phase 0.11+ 검토.
    """

    def __init__(self) -> None:
        self._renderers: dict[str, StrategyRenderer] = {
            "price_drop": SevenSplitRenderer(),
            "support_level": SevenSplitRenderer(),  # SupportSlot 동일 매핑
        }
        self._default: StrategyRenderer = DefaultRenderer()

    def get(self, strategy_id: str) -> StrategyRenderer:
        """Lookup. 미등록 strategy 는 DefaultRenderer 반환 (Acceptance
        Criteria 3 — 신규 dummy strategy 추가 시 코어 변경 zero)."""
        return self._renderers.get(strategy_id, self._default)

    def register(
        self, strategy_id: str, renderer: StrategyRenderer,
    ) -> None:
        """런타임 등록 — 외부 plugin 또는 테스트용."""
        self._renderers[strategy_id] = renderer
```

## 5. ADR-3: DrawdownEpisodeDetector — 전략 무관 분석 모듈

### 5.0 사용자 spec 의 의도

> equity curve 만 입력받아 동작. 임계치 (예: -5%) 이상 peak-to-trough
> 구간을 episode 로 추출. Episode 메타: 시작 / 저점 / 회복 시점, MDD%,
> duration, 회복 여부.

### 5.1 결정 — Application layer 의 strategy-agnostic 분석 모듈

| 옵션 | 채택 | 근거 |
|---|---|---|
| **A) `src/application/reporting/episode.py` (DrawdownEpisode dataclass + detector)** | **채택** | strategy-agnostic. Equity curve (BacktestResult.snapshots → total_value series) 만 입력 |
| B) Domain layer 추가 | 거부 | Domain 의 본질 (의사결정 + 잔고) 외 분석 — application 적합 |

### 5.2 DrawdownEpisode dataclass

위치: `src/application/reporting/episode.py` (신규)

```python
from __future__ import annotations
from dataclasses import dataclass
from datetime import date
from decimal import Decimal


@dataclass(frozen=True)
class DrawdownEpisode:
    """Equity curve 의 1 개 drawdown episode.

    peak_date → trough_date 손실 구간 + recovery_date (옵션, peak 회복
    시점). 회복 안 된 경우 ``recovered=False`` / ``recovery_date=None``.
    """
    peak_date: date
    peak_value: Decimal
    trough_date: date
    trough_value: Decimal
    recovery_date: date | None
    recovered: bool
    drawdown_pct: Decimal  # negative (예: Decimal("-22.6639"))
    duration_days: int  # peak_date 부터 recovery_date (또는 series end)
    asset_code: str | None = None  # None = portfolio level, else asset code
```

### 5.3 Detector

```python
from collections.abc import Sequence


def detect_drawdown_episodes(
    equity_curve: Sequence[tuple[date, Decimal]],
    threshold_pct: Decimal = Decimal("-5"),
    *,
    asset_code: str | None = None,
) -> list[DrawdownEpisode]:
    """Equity curve 에서 |drawdown| ≥ |threshold_pct| 인 episode 추출.

    Algorithm:
    1. running peak_value (peak_date) 추적
    2. 각 (date, value) 에서 drawdown = (value - peak_value) / peak_value * 100
    3. drawdown ≤ threshold_pct (예: -5%) 진입 시 episode 시작 (peak 박제)
    4. trough = episode 내 minimum value
    5. value ≥ peak_value 회복 시 episode 종료 (recovered=True,
       recovery_date 박제)
    6. 마지막 episode 회복 안 된 경우 recovered=False,
       recovery_date=None, duration = series_end - peak_date

    Args:
        equity_curve: (date, value) sorted ascending by date.
        threshold_pct: 음수 (예: Decimal("-5") for -5%).
        asset_code: portfolio level = None, asset level = code.

    Returns:
        List of episodes ordered by peak_date.
    """
    ...  # 구현은 Step A.3 sub-step
```

### 5.4 임계치 정책 — Open Question Q1 답변

| 옵션 | 채택 | 근거 |
|---|---|---|
| **A) `-5%` 기본 + yaml/CLI 설정 가능** | **채택** | Phase 0.7.3 MDD -8.27% / Phase 0.9.1 -22.66% / Phase 0.9.2 -37.65% 모두에서 다수 episode 추출 가능 |
| B) `-10%` 기본 | 거부 | Phase 0.7.3 의 -8.27% MDD 가 episode 0 개 → 분석 불가 |
| C) `-3%` 기본 | 거부 | noise 가능성 (단기 fluctuation) |

→ default `-5.0%`. yaml `reporting.drawdown_threshold_pct` 또는 CLI
`--threshold` 로 override 가능.

### 5.5 멀티 자산 episode 정의 — Open Question Q4 답변

| 옵션 | 채택 | 근거 |
|---|---|---|
| **A) Portfolio level (default) + asset level (옵션) + both** | **채택** | Portfolio = 전체 손실 진단 (사용자 의도). Asset = 종목별 lock-in 진단 (Phase 0.9 발견 패턴 — 005930/015760/097950 split_level=7). 양쪽 모두 가치 |
| B) Portfolio only | 거부 | Phase 0.9 의 종목별 lock-in 진단 불가 |
| C) Asset only | 거부 | "전체 손실 진단" 본질 약화 |

→ CLI `--episode-scope portfolio | asset | both` (default `portfolio`).
yaml 설정 가능.

- Portfolio scope = `BacktestResult.snapshots[i].total_value` series
- Asset scope = `BacktestResult.snapshots[i].valuations[j].market_value`
  series (per-asset)
- Both = 둘 다 추출, HTML index 에 분리 표기

### 5.6 Episode 회복 판정

`recovered=True` 조건: episode 내 어느 시점에 `value >= peak_value` 도달.
`recovery_date` = 첫 회복 시점.

마지막 episode 가 recovery 안 된 경우 (예: Phase 0.9.1 의 -22.66% MDD
가 백테스트 종료 시점에도 회복 안 됨) `recovered=False`,
`recovery_date=None`, `duration_days = series_end - peak_date`.

### 14.5 결정 2 — 포매팅 정책 박제 (synth #5 + Critic patch C1)

`src/adapters/reporting/formatters.py` (신규) 가 표시 layer 의 단일 진입점:

| Helper | 정책 | 비고 |
|---|---|---|
| `format_money(amount, currency="KRW")` | KRW = ``₩`` prefix + 정수 + 천단위 콤마. 그 외 = ``<CURRENCY> <2-decimal>`` | 음수 = ``-`` prefix |
| `format_pct(value, *, places=2, signed=True)` | 부호 옵션 + 정밀도 cut. ``ROUND_HALF_UP`` | default places=2 |
| `format_price(value, currency="KRW")` | `format_money` 패턴 동일하지만 음수 prefix 없음 (가격 = 양수) | — |
| `format_quantity(value)` | 정수 → 콤마. 소수 → 2 decimals | — |
| `format_date(d)` | ISO ``"2020-02-12"`` | — |
| `format_datetime_kst(dt)` | UTC midnight 일봉 → ``"2020-02-12 (수)"``. 시간 ≠ 0 (intraday) → ``"2020-02-12 09:30 KST (수)"`` (Asia/Seoul 변환) | CLAUDE.md §3.1 정합 — naive 입력은 UTC 간주, 표시만 변환 |

**금지 (CLAUDE.md §2.1 정합)**: float 미경유. 모든 정밀도 절단은
`Decimal.quantize(..., ROUND_HALF_UP)`.

### 14.6 결정 3 — Cycle 페어링 정책 박제 (synth #4 + Critic patch C2)

`src/application/reporting/cycle_pairing.py` (신규, application layer):

- **Primary 매칭** = `TradeView` list-order FIFO (ADR 0002 §5.4
  sells-then-buys 흐름 보존 — `trades_from_decisions` 가 emit 순서
  유지)
- `entry_price` annotation = **diagnostic only**, 매칭 키 아님
  (slot-level avg-cost 일 가능성 — Critic finding 1)
- 같은 종목 같은 날 SELL → BUY 분리: SELL 이 직전 cycle 종료, BUY 가
  새 cycle 시작 (Phase 0.9.2 episode_1 의 ``2020-02-14 097950
  SELL → BUY`` 케이스 정합)
- `Cycle` = local-frozen dataclass — TradeView peer 승격 X (Option B
  의 `TradeCycleView` 거부)

**Truthfulness 라벨링** (Critic patch C3):
- 종목별 cycle table 컬럼 헤더 = ``realized_pnl (FIFO 표시)``
- AC5 disclaimer: 본 cycle 의 ``realized_pnl`` 은 **표시값** 이며,
  실제 strategy 의 avg-cost / 부분체결 등 정확한 매칭과 차이 가능.
  정확한 strategy realized P&L = Phase 1 KIS API + 실거래
  reconciliation 단계 별도 정의 (ADR 0007 trigger)

CLAUDE.md §8.1 (모든 결정은 reasoning 보존) + §13.3 (친절한 추가 금지)
정신 — 표시값을 ground truth 로 오해하지 않도록 명시.

### 14.7 결정 4 — KPI Strip 정의 박제 (Critic patch C1)

Episode 페이지 상단 5 deterministic KPIs (always-available facts only):

1. **Drawdown** — `format_pct(episode.drawdown_pct)`
2. **Duration** — `f"{episode.duration_days}일"`
3. **Recovered** — yes/no 배지 (CSS class `recovered-yes/no`)
4. **Trades** — `f"{n_buys} buys / {n_sells} sells"`
5. **Invested** — `Σ buy annotations["actual_cost"]` (fallback `price * quantity`), `format_money`

**Realized P&L 은 KPI strip 미포함** — 종목별 cycle table 안에서만
표시 (synth #5). KPI strip = 항상 deterministic 한 값만, 매칭 불확실
값은 자리 잡지 않음.

### 14.8 결정 5 — 표시 vs 모델 분리 원칙 박제

CLAUDE.md §2.1 (계산은 Decimal) + §3.1 (저장은 UTC) 보강 박제:

- **모델 진실** = 도메인 / application layer / 영구화 데이터: Decimal
  full precision + UTC ISO timestamp + asset.code
- **표시 layer** = `src/adapters/reporting/formatters.py` + `html_writer.py`
  의 helper: 정밀도 cut + 통화 prefix + KST 변환 + 종목 표시명

표시 helper 는 모델 진실을 변경하지 않음. `BacktestResult.snapshots` /
`Decision.reasoning` / `OHLCV` / `Trade.timestamp` 등 모델 측은 동결.

helper `_enrich_with_slot_number(annotations, slot_number, *, asset_code, side)`
도입. 핵심 정책:

- **Source**: `BuyActionRecord.slot_number` / `SellActionRecord.slot_number` —
  도메인 모델의 typed field. `models.py:1267` (Buy) + `models.py:1250` (Sell)
- **Sink**: `TradeView.annotations["slot_number"]` — view-only dict (frozen
  dataclass field, 영구화 X)
- **Naming**: 도메인 vocabulary `slot_number` 그대로. BUY / SELL 모두 동일 키
- **Mutation rule**: 도메인 `reasoning` dict 절대 변경 X — `dict(...)` 로 복사
  후 view-side 만 수정. AC: `domain reasoning dict unchanged` test
- **Clean Architecture 준수**: application layer 는 도메인 typed field (inner
  layer) 를 read-only 로 사용 — inner→outer 의존 없음. Adapter (renderer) 는
  application 이 채운 annotations 를 read — outer→inner 의존만 존재. ADR 0006
  §8 의존 다이어그램 정합

### 16.4 결정 2 — Adapter (`SevenSplitRenderer`) 는 도메인 명명 align

`src/adapters/reporting/renderers/seven_split.py:92-97` `_slot()` 의 read key
변경:

| Before (pre-Phase-0.5 fossil) | After (uniform domain-aligned) |
|---|---|
| `key = "split_number" if BUY else "slot_number"` | `key = "slot_number"` (uniform) |

**전사 (rename history)**: `split_number` 는 Phase pre-0.5 시절 renderer-internal
명칭이었음. 도메인은 Phase 0.5 부터 `slot_number` 로 통일했고, 본 어댑터는
Phase 0.10.z 에서 도메인 명명에 align — half-done rename 의 마무리. fresh
renaming 아님.

ADR §4.3.1 박제 (slot palette tab10 + B1~B7/S1~S7 라벨 spec) 그대로 보존 —
read key 명명만 align (`split_number` → `slot_number`). 시각 / 색상 / 라벨
시멘틱 변경 zero.

### 16.5 결정 3 — 엄격 invariant (no-collision)

`_enrich_with_slot_number` 는 **`assert "slot_number" not in annotations`**
로 시작. 사유:

- 오늘 시점 검증 (Critic verified): 어떤 strategy 도 `slot_number` 를
  reasoning 에 emit 하지 않음. PriceDropStrategy / SupportLevelStrategy 는
  `target_slot_number` (다른 키) 를 사용. ProfitTargetSell 는 `entry_price`,
  `current_price`, `profit_pct`, `profit_target_pct` 사용
- 미래 회귀 보호: future strategy 가 reasoning 에 `slot_number` 를 추가
  emit 하면 fail-fast (AssertionError) → 즉시 가시화. `setdefault` 같은 silent
  fallback 거부
- 거부된 alternative: `setdefault("slot_number", str(record.slot_number))` —
  collision 시 silent (둘이 다른 값일 때 view 가 stale value 표시) — 거부

### 16.6 결정 4 — Renderer-agnostic application layer (E4 증명)

Application layer 는 어떤 renderer 의 read key 도 모름. `_enrich_with_slot_number`
는 `slot_number` 라는 도메인 명명만 사용 — 우연히 `SevenSplitRenderer` 가
같은 키를 read 하지만 **변경 가능**. 미래 다른 renderer (e.g. MA-cross
strategy renderer) 가 `slot_number` 를 read 하든 다른 키를 read 하든
application layer 변경 zero.

증거: `tests/unit/test_trade_view.py::TestSlotNumberEnrichment::test_strategy_neutral_uniform_key`
— `strategy_id="ma_cross_dummy"` 로도 동일 enrichment 동작.

### 16.7 결정 5 — Vestigial `_INT_KEYS` 정책

`src/adapters/reporting/html_writer.py:575` `_INT_KEYS = frozenset({"split_number",
"slot_number"})` 는 annotation mini-table 의 int 포매팅 dispatch. Phase 0.10.z
박제 후 BUY annotations 에 `split_number` 가 더는 들어오지 않음 → `split_number`
부분은 dead code. 그러나:

- 후방 호환: 가상의 future renderer 가 `split_number` 를 직접 emit 하는 경우 (e.g.
  레거시 데이터 import) annotation table 에서 int 포매팅이 여전히 가능
- 변경 비용 < 이익: 1 단어 제거가 실용적 가치 zero
- **Cleanup deferred to Phase 0.11+**

본 § 는 의식적 박제 — 후속 cleanup 시 본 §16.7 인용.

### 18.C 결정 — Sharpe / Calmar episode-내 + Risk-Adjusted Metrics 섹션

`src/application/reporting/risk_metrics.py` 신규 — application view-model
layer (TradeView / EpisodeReportResult / StrategyInfo 패턴 정합). 도메인
변경 zero, Protocol 변경 zero, 신규 의존성 zero.

#### 18.C.1 EpisodeRiskMetrics dataclass

Frozen, in-memory only. 3 fields:
- `sharpe: Decimal | None` — episode window annualized Sharpe
- `calmar: Decimal | None` — episode window Calmar (CAGR / |MDD|)
- `recovery_efficiency: Decimal | None` — `(recovery_date - trough_date) /
  (trough_date - peak_date)`

#### 18.C.2 None vs Decimal(0) disambiguation (CRITICAL)

`metrics.sharpe_ratio` / `calmar_ratio` 가 degenerate case (σ=0, MDD=0)
에서 `Decimal(0)` sentinel 반환. View layer 에서 이를 `None` 으로 wrap:
- Sharpe: `has_nonzero_return_variance(window) == False` → `None`
- Calmar: `max_drawdown(window) == Decimal(0)` → `None`
- Recovery efficiency: `not episode.recovered OR peak→trough days <= 0` → `None`

**금지**: `Decimal(0)` 직접 표시 — "Sharpe 0.00" 은 "zero excess return" 으로
오해. 금융 표시 context 에서 **misinformation bug** (CLAUDE.md §2.1 / §5.2
돈 관련). Critic iter 1 CRITICAL finding 박제.

**Implementation**: `has_nonzero_return_variance(snapshots) -> bool` —
`src/application/metrics.py` 신규 public predicate (DRY 정합 — Sharpe σ
계산 재사용).

#### 18.C.3 Section omit policy

Factory `compute_episode_risk_metrics(snapshots, episode) -> EpisodeRiskMetrics | None`:
- `None` ← window snapshot 수 <2 (section omit signal)
- `EpisodeRiskMetrics` ← ≥2 snapshots (각 field 는 degeneracy 시 `None`)

HTML helper `_render_risk_adjusted_metrics(metrics)`:
- `metrics is None` → `""` (section + header omit)
- 모든 field `None` (defensive) → `""`
- non-None field 만 row 로 render (row-level omit OK, section-level omit
  preferred when 모두 None)

**원칙**: Section-level omit > row-level N/A — Phase 0.10.x §14.7 "always-
available facts only" 정신 정합.

#### 18.C.4 Sort invariant

`compute_episode_risk_metrics` 가 입력 snapshots 를 `snapshot_date` 로
defensive sort (caller 가 dict 등 unsorted 로 전달해도 결과 deterministic).
`metrics._sorted_values` (`metrics.py:36-45`) 패턴 정합.

#### 18.C.5 HTML 위치

`<h1>` → `strategy_info` → KPI strip → **Risk-Adjusted Metrics** (신규) →
Episode 메타데이터 → 차트 (per-symbol). KPI strip 과 같은 "top-level
summary" 자리. KPI strip 의 5 deterministic facts 와 분리 — 위험조정
지표는 "window stats" 개념 (Phase 0.10.x §14.7 정합).

#### 18.C.6 거부된 alternatives

- **Win rate** in Risk-Adjusted Metrics tier — FIFO realized P&L ground truth
  위반 (§14.7 박제). 별도 `_render_symbol_groups` cycle-summary line 이 적합 —
  Phase 0.10.bb.d / Phase 0.11+ candidate (§18.E).
- **위험조정 지표 KPI strip 추가** — Phase 0.10.x §14.7 박제 "5 deterministic
  KPIs only" 위반.
