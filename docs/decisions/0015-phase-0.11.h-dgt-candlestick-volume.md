## §1 Decisions

### §1.1 Phase Essence

DGT 백테스트 리포트의 가격 차트를 **close-price 라인 → OHLC 캔들스틱 + 거래량** 으로

두 독립적 chart 시스템 동시 업그레이드:
1. `src/research/dgt/kakao_dgt_backtest.py` — 사용자가 실제 실행하는 CLI
2. `src/research/visualization/_dgt_renderer.py` — Phase 0.11.c permanent renderer

**스코프 경계**: 차트 변경만. 전략 재검증 / inner ring 변경 / 새 의존성 추가 없음.

### §1.2 D-Evolution Note — ADR 0009 D4 관계 명시

ADR 0009 D4 는 "matplotlib + mplfinance only 채택" 을 결정했다. Phase 0.11.c 에서
`_DGTVisualizationRenderer` 는 캔들스틱을 *사용하지 않는 선택*을 했다
(ADR 0009 §2.2: "close line + grid envelope + reference price line + BUY/SELL scatter markers").
당시 모듈 docstring에 "캔들 미필요" 로 박제.

**본 ADR 0015 의 결정은 ADR 0009 D4 reversal 이 아니다.** 이유:

- ADR 0009 D4 는 backend 를 "matplotlib + mplfinance only" 로 승인했다. 이 결정은
  *"캔들을 쓰지 않는다"* 가 아니라 *"Plotly 같은 새 dep 추가 없이 기존 matplotlib
  primitives 를 사용한다"* 가 본질이다 (ADR 0009 D4 거부 이유: `pyproject.toml`
  §0 trigger 회피).
- 캔들스틱 추가 = **이미 승인된 matplotlib 프리미티브** 사용 — 새 dependency 없음.
- `mplfinance` 는 ADR 0009 D4 에서 *허용*되었지만, Phase 0.11.h 에서는 수동 그리기
  방식을 선택 (Option A synthesis, §1.3 D1 참조). mplfinance 미사용은 결정의 reversal
  이 아니라 더 안전한 방식의 선택.

따라서 본 ADR 은 ADR 0009 D4 의 **진화(evolution)**이며 supersede 가 아니다.
ADR 0009 §2.2 의 `_DGTVisualizationRenderer` 구현은 Phase 0.11.h 에서 업그레이드된다
(캔들+거래량 2-panel 추가, 기존 overlay/marker 보존).

### §1.3 Key Decisions (D1~D8)

#### D1 — Unified Approach: Option A Synthesis (shared `_draw_candles` + `_draw_volume` helper)

**결정**: 새 파일 `src/research/dgt/_candles.py` 에 `_draw_candles(ax, bars, *, width_frac)` 와
`_draw_volume(ax, bars, *, width_frac)` 순수 matplotlib 프리미티브 helper 를 구현.
**BOTH** `kakao_dgt_backtest.py` 와 `_dgt_renderer.py` 가 이 shared helper 를 호출.

거부된 대안:

| 대안 | 거부 이유 |
|------|-----------|
| **Option B — mplfinance external-axes mode** | beta-pinned (`0.12.10b0`) 안정성 위험 + external-axes volume 지원 미문서화 + overlay(grid envelope/scatter markers) 와 충돌 위험 (DD2). mplfinance 를 multi-panel 에서 거부하면서 single-panel 에서 허용하는 것은 자기모순 — 동일한 overlay 위험이 존재. |
| **Option C — per-strategy figure composite** | 리포트 *구조* 변경 (sharex 정렬 + combined equity panel 소실) — P3 위반 + 스코프 초과. |
| **Option 5a — native `mpf.plot()` for single-panel `_dgt_renderer.py` only** | Option B 거부 논리와 자기모순: `_draw_grid_envelope` + `_draw_reference_price` 가 mpf-returned axis 를 targeting 해야 하므로 동일한 DD2 overlay 위험. 두 파일에 서로 다른 구현 (manual + mpf) = P2 위반. |

**채택 근거 (Option A)**:
- `plt.subplots(N+K, 1)` 레이아웃, `sharex`, `gridspec_kw` 모두 untouched — blast radius 최소.
- `_draw_grid_levels`, BUY/SELL `ax.scatter`, equity panel, titles/legends 변경 zero (동일 `ax` + 동일 date x-axis 유지, DD2 충족).
- figure-ownership 충돌 없음 (multi-panel AND single-panel 모두).
- 하나의 candle 구현으로 두 chart 시스템 커버 (P2 충족).
- mplfinance 버전 coupling 없음 (permanent research tooling 에서 중요).

#### D2 — Namespace Placement: `_candles.py` in `src/research/dgt/`

**결정**: `_candles.py` 를 `src/research/dgt/` 에 배치.

**근거**: `kakao_dgt_backtest.py` 는 `dgt/` 에 있고, `dgt → visualization` import 는
`scripts/check_namespace.sh` (line 49-58) 에 의해 **FORBIDDEN** 이다. 따라서
`kakao_dgt_backtest.py` 가 `visualization/` 에서 helper 를 import 하는 것은 불가능.
반대로 `visualization → dgt` import 는 **ALLOWED** (outer→inner read, `check_namespace.sh`
line 42-46 comment 정합) — `_dgt_renderer.py` (`visualization/` 소속) 가
`src.research.dgt._candles` 를 import 하는 것은 합법.

오해 방지: `check_namespace.sh` 가 차단하는 것은 `dgt` 코드에서 `visualization` 으로의
**역방향 import** 이다 (파일 위치 자체가 아님). `_candles.py` 는 `dgt/` 에 위치하지만
`visualization` 에 대한 import 를 포함하지 않으므로 규칙 위반 없음.

#### D3 — Accepted Visual Tradeoff: DGT-renderer candles ≠ Phase 0.10 chart.py candles

**결정**: `_dgt_renderer.py` 의 캔들이 `src/adapters/reporting/chart.py` (Phase 0.10) 의
native-mpf 캔들과 시각적으로 다를 수 있음을 수용.

**근거**: 두 차트는 다른 리포트/워크플로우에 속한다 (`chart.py` = episode 리포트,
`_dgt_renderer.py` = DGT full-period 연구 리포트). 두 시스템 간 시각적 일관성은 요구사항이
아니다. 하나의 구현이 두 개의 발산 구현보다 유지보수가 단순하다 (P2).

`chart.py` 는 **read-only 패턴 참조** 대상이며 (P1), Phase 0.11.h 에서 절대 편집하지 않는다.

#### D4 — Volume Layout: One Shared Volume Panel per Figure

**결정**: figure 당 하나의 공유 volume panel 추가. per-strategy twinx overlay 거부.

**근거**:
- `_render_comparison_chart` 는 single-asset mode 에서만 실행된다
  (`kakao_dgt_backtest.py:~1119`). 모든 N strategy panel 이 동일 자산의 데이터를 보여준다 —
  volume 은 N 번 중복 그리면 redundant noise.
- `_render_per_stock_charts` 는 multi-asset mode 에서 각 figure = 하나의 종목이다.
  동일 figure 내 모든 strategy panel 은 동일 종목의 데이터.
- **twinx per panel 거부**: 각 가격 패널 오염 + N 번 동일 데이터 중복.

**레이아웃 변경 (comparison chart)**: `plt.subplots(n_strategies + 1, 1)` →
`plt.subplots(n_strategies + 2, 1)`. `height_ratios = [3]*n_strategies + [1, 2]`.
figsize = `(14, 3.5 * n_strategies + 1.5 + 3.0)`.

**레이아웃 변경 (per-stock chart)**: `plt.subplots(n_strats, 1)` →
`plt.subplots(n_strats + 1, 1)`. `height_ratios = [3]*n_strats + [1]`.
figsize = `(14, 3.5 * n_strats + 1.5)`.

#### D5 — Volume Data Source: `bars: list[OHLCV]`, NOT `_DGTSnapshot`

**결정**: volume 데이터는 `bars: list[OHLCV]` 의 `bar.volume` 에서 가져온다.
`_DGTSnapshot` (`results.py:19-29`) 은 `trade_date`, `close_price`, `total_value` 만 보유 —
`volume` 필드 없음. `_DGTSnapshot` 에서 volume 추출 불가.

**R10 domain-equality assertion**: `_draw_candles` 는 `bars` date domain 에서,
`_draw_grid_levels` 는 `result.daily_snapshots` dates (`kakao_dgt_backtest.py:503`) 에서
동작한다. 모든 runner 에서 두 도메인은 동일한 OHLCV 피드에서 유래 — 날짜 도메인이
동일해야 한다. `_render_comparison_chart` 와 `_render_per_stock_charts` 각각에 다음
assertion 추가:

```python
assert [b.trade_date for b in bars] == [s.trade_date for s in result.daily_snapshots]
```

assertion 발동 시 = runner 의 버그 (chart 의 버그 아님) — loud failure.

#### D6 — No New Dependency

**결정**: `pyproject.toml` 변경 없음. `reporting` extra 에 이미 matplotlib / mplfinance /
pandas 포함 (`pyproject.toml:32-36`). CLAUDE.md §0 trigger 발동 없음.

Note: mplfinance 는 ADR 0009 D4 에서 승인되었으나 Phase 0.11.h 에서 사용하지 않는다 —
Option A synthesis 의 수동 그리기 방식이 overlay 안전성과 일관성 면에서 더 적합하다고 판단.

#### D7 — Figure-Leak Invariant 절대 보존 (P4)

**결정**: 추가된 volume panel 이 있더라도 `try/finally` + `plt.close(fig)` 패턴을 모든 render
함수에 보존. `plt.get_fignums() == []` after every render.

근거: ADR 0009 R8 / ADR 0006 §17.8 패턴 상속. volume panel 추가는 figure-leak 위험을
높이지 않는다 — 같은 `fig` 에 axis 가 추가될 뿐. 단 `try/finally` 가 누락되면 exception 시
volume axis 도 leak 되므로 패턴 유지가 load-bearing.

#### D9 — Bar-Count-Adaptive Figure Width (Density Improvement, user-requested scope addition)

**결정**: `_render_comparison_chart` 와 `_render_per_stock_charts` 의 figsize width 를
고정 14 inches 에서 **bar count 에 비례하는 adaptive width** 로 변경.
공식: `width = min(40, max(14, n_bars / 55))`.

- n_bars ≤ 770 (약 3년): 14 inches (최소)
- n_bars = 1250 (5년): ≈ 22.7 inches
- n_bars = 2000: ≈ 36.4 inches
- n_bars ≥ 2200: 40 inches (최대)

**근거**: 5-year (~1250 candle) 차트에서 고정 14 inches width 는 candle body 가 너무
조밀해진다. Adaptive width 는 bar 수에 비례해 figure 를 확장 — 캔들 간격이 일정하게
유지됨. 상한 40 inches 는 메모리/파일 크기 과대 방지. `_dgt_renderer.py`(단일-period
renderer) 는 `_FIGURE_WIDTH_PX` / `_FIGURE_DPI` 고정 (1600x900) — 변경 없음
(단일 period 특성상 `bbox_inches="tight"` 로 충분).

**적용 범위**: `kakao_dgt_backtest.py` 의 `_render_comparison_chart` + `_render_per_stock_charts`
두 함수. `_dgt_renderer.py` 는 미적용.

#### D8 — Decimal-to-float Boundary

**결정**: OHLCV 의 `open`, `high`, `low`, `close`, `volume` 은 `Decimal` 타입. 모든 변환은
`_draw_candles` / `_draw_volume` 내부 matplotlib array 생성 시점에만 발생 (P5).

```python
# ✅ 변환 위치 — plotting boundary 에서만
opens  = [float(b.open)  for b in bars]
highs  = [float(b.high)  for b in bars]
lows   = [float(b.low)   for b in bars]
closes = [float(b.close) for b in bars]
```

`_DGTSnapshot.close_price` 역시 기존 코드가 이미 float 변환을 plotting 시점에 하고 있음 —
패턴 불변.
