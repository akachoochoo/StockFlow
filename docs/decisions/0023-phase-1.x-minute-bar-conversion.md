## 6. § Idempotency Key 형식 (D10)

### 6.1 7세그 형식

```
{fqn}:{date}:{HHMM}:{side}:grid:{level_idx}
예: src.domain.strategies.grid_minute:2026-06-15:1042:buy:grid:5
```

- `fqn` = `src.domain.strategies.grid_minute.GridMinuteStrategy` 의 FQN
- `date` = `YYYY-MM-DD` (한국 거래일)
- `HHMM` = `HHMM` (KST, 0900~1530)
- `side` = `buy` / `sell`
- `grid` = 형식 판별 토큰 (ADR 0022 D17 계승)
- `level_idx` = 0..n (grid 레벨 인덱스)

### 6.2 Parser 분기

`src/domain/order_keys.py:parse_order_key()` 확장:
- 5세그 → 기존 split 키 (`{fqn}:{date}:{side}:{slot_number}`)
- 6세그 → ADR 0022 D17 일봉 grid 키 (`{fqn}:{date}:{side}:grid:{level_idx}`)
- 7세그 → 본 ADR D10 분봉 grid 키 (`{fqn}:{date}:{HHMM}:{side}:grid:{level_idx}`)
- 그 외 → `OrderKeyError` (CLAUDE.md §6.3 침묵 실패 금지 → halt)

### 6.3 PendingSettler 분기

`src/use_cases/pending_settler.py` 의 `parse_order_key` 호출 분기:
- 5세그 → split settle (기존)
- 6세그 → 일봉 grid settle (ADR 0022 D21, 동결 상태에선 미사용)
- 7세그 → 분봉 grid settle (신규 경로, 5th ring 까지 본 ADR §X.X.2 확장)

### 6.4 ADR 0019 호환

`orders.idempotency_key` 컬럼 = TEXT (가변 길이) — 7세그 최대 길이 측정 후 박제. 예상: ~120 chars (FQN ~70 + date 10 + HHMM 4 + side 4 + "grid" 4 + level 2 + 구분자 6 = ~100). DB schema 변경 zero (AC10).

## 7. § Session Handling (D16)

### 7.1 정규장 (09:00~15:30 KST) 전구간 1분 cron

- 1분마다 OS cron → `trading minute-live` 호출 → lock file 직렬화.
- `is_market_open(now)` 호출:
  - `now ∈ [09:00, 15:30] KST` 거래일 → True → grid 결정 + 주문 제출
  - 그 외 → False → 즉시 exit (no-op)
- 동시호가 구간 (15:20~15:30) 특별 처리:
  - cron 은 정상 호출 (D16-A).
  - grid 결정 = pass (주문 제출 zero) — KRX 동시호가 단일가 메커니즘 회피.
  - grid 상태 갱신 (avg_cost / level history) 은 정상 진행.

### 7.2 KIS API 가용성

- 09:00 직전 시세 = 전일 종가 + 호가창 (KIS `inquire-price`).
- 09:00 시가 형성 후 1분봉 = `inquire-time-itemchartprice`.
- 15:30 종가 형성 시각까지 1분 간격 호출.

### 7.3 휴장일 / 부분 거래일

- KIS `inquire-holiday` (Stage 3/4 follow-up) 또는 explicit_holidays config 주입.
- 휴장일 cron 호출 → `is_market_open=False` → 즉시 exit.
- 부분 거래일 (반장) = 별도 결정 라운드 (R10 후속).

## 12. Why (선택 근거)

### 12.1 Q1=일괄 전환 (D1)

- **일관성**: backtest↔dry-run↔live 동일 의사결정 주기 = G2 진성 동등성 가능.
- **분리 운영의 위험**: 일봉 + 분봉 이중 cron = §10.1 룰 이중 인프라 + lock 충돌 + 디버깅 복잡도 폭증.
- **위험 수용**: ADR 0022 §13 인프라 동결 (Q5/D5) 로 회귀 zero 보장 + 코드 보존 = 분봉 실패 시 즉시 복구 가능.

### 12.2 Q4=cron 1분 (D4)

- **§10.1 본질 보존**: "단일 프로세스 cron" 의 핵심 = 데몬 회피 + lock 자연 직렬화 + OOM/장애 자동 격리. 1분 주기 호출 = 데몬 형태 아닌 cron 호출.
- **장기 안정성**: 데몬 = supervisord/systemd 의존 + 단일 장애점. cron 1분 = OS native + 각 호출 독립.
- **테스트 단순성**: 단일 호출 단위 = 회귀 테스트 자연 (390번 호출이 아닌 1회 호출 검증).

### 12.3 Q8=Split 폐기 (D8)

- **ADR 0022 D2 정합**: DGT = MDD 방어 전용 권고 + §11.21 권고 A risk-adjusted 우위 → DGT-only 운영 = 사용자 의도 정합.
- **인프라 단순화**: 분봉 split + 분봉 DGT 이중 운영 = ADR 0012 §16.4 sell strategy 단일 가정 위반 + 이중 SELL 주체 충돌.
- **회귀 보호**: split 코드 = 존속 (D17) + 운영 zero = 회귀 zero + 미래 결정 라운드에서 부활 가능.

### 12.4 Q14=ADR 0022 D28 그대로 (D14)

- **변경 최소**: 게이트 동일 → 검증 절차 표준화.
- **자동 강도 증가**: 분봉 = sample size ×390 (10영업일 = 3900 cycles) → 통계적 강도 자동 ↑.
- **R10 acknowledge**: 강세장 단일 윈도 의존 위험 = 후속 결정 라운드 보류 (즉, 본 ADR 게이트 통과 후 multi-window 분봉 재검증 별도 라운드).

## 13. Alternatives Considered

### 13.1 Q1-A (Backtest+dry-run 만 분봉, live=일봉 유지)

거부 — D12 G2 진성 동등성 본질 위반. backtest↔dry-run 분봉, live 일봉 = 이중 운영 + 비교 불가능 + Phase 0.11.a R1 반복.

### 13.2 Q1-C (Backtest only 분봉)

거부 — 사용자 의도 ("dry-run 시작") 와 불일치 + 분봉 검증의 운영 가치 미실현.

### 13.3 Q4-B (장중 단일 데몬)

거부 — §10.1 룰 위반 + 단일 장애점 + OOM 자동 격리 불가 + supervisord/systemd 의존 추가.

### 13.4 Q4-C (KIS websocket streaming)
