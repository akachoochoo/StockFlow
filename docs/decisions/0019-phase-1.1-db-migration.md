# ADR 0019 — Phase 1.1 Stage 4.5: DB Schema Migration (Order Cost/Routing Fields)

> **Status**: 박제 (Phase 1.1 Stage 4.5, 2026-05-22). ADR 0012 D17 위임 해소.
> **Date**: 2026-05-22
> **성격**: Write (Stage 5) 이전 **hard gate** — write 가 존재하지 않는 컬럼을 소비하지 않도록 선결 provisioning. consensus 리뷰 BLOCKING-1 (DB 마이그레이션 실행 누락) 해소.

## 1. Context

Phase 1.1 build (Stage 0–7) 진행 중 consensus 리뷰가 **BLOCKING**을 발견: `OrderResult` / `orders` 테이블에 `tax` / `commission` 컬럼 부재. `db.py`는 "no Alembic" 정책이며, `tax`/`commission`은 5th ring (`research/dgt`)에만 존재 → inner ring에서 도달 불가. write (Stage 5) 및 비용 교차검증이 존재하지 않는 컬럼을 소비하면 첫 실거래 체결 시 잔고 불일치 risk.

추가로 ADR 0020 §2.2 가 cancel 라우팅에 `KRX_FWDG_ORD_ORGNO`가 필요함을 확정 — order-cash 응답의 `ODNO`(→ `broker_order_id`)만으로는 order-rvsecncl(취소)을 호출할 수 없음.

따라서 신규 **Stage 4.5 (Schema Migration, ADR 0019)** = write 이전 hard gate. 본 ADR은 ADR 0012 D17이 위임한 마이그레이션 스크립트 + 검증 + 백업/rollback 절차를 박제한다.

---

## 2. Decision

`orders` 테이블 + `OrderResult` / `Order` 도메인 모델에 **nullable 3 컬럼 additive 추가** (전부 `None` default = 기존 행/코드 100% 호환):

| 컬럼 | 도메인 타입 | DB 타입 | 의미 | 채우는 시점 |
|------|-------------|---------|------|-------------|
| `tax` | `Decimal \| None` | `TEXT` (nullable) | 거래세 | provisional None → Stage 7 실응답 검증 후 |
| `commission` | `Decimal \| None` | `TEXT` (nullable) | 수수료 | provisional None → Stage 7 실응답 검증 후 |
| `broker_org_no` | `str \| None` | `TEXT` (nullable) | `KRX_FWDG_ORD_ORGNO` (cancel 라우팅) | Stage 5 cancel 에서 채움 |

### 2.1 provisional (ADR 0020 §4 정합)

KIS 기본 응답(order-cash / inquire-balance)은 **per-order 세금·수수료를 직접 제공하지 않는다** (계좌요약 `thdt_tlex_amt` = 당일 제비용 *총액*만). 따라서:

- `tax` / `commission` 은 당분간 항상 `None`. per-fill 귀속(attribution)은 Stage 7 모의투자 실응답 검증 후 별도 결정.
- `broker_org_no` 는 Stage 5 cancel(order-rvsecncl) 구현 시 order-cash 응답에서 캡처하여 채움.

컬럼만 미리 provisioning — 값 채우기 로직은 본 ADR scope 외.

### 2.2 도메인 검증 (순수 additive)

- `tax` / `commission`: `_to_decimal` coercion (None-aware) + 음수 거부 (`< 0` raise; 세금/수수료는 ≥0). `filled_price` 패턴 미러 (단 filled_price 는 `<= 0` 거부, 비용은 `< 0` 거부 — 비용 0 은 유효).
- `broker_org_no`: `str | None`, 검증 없음.
- `Order.from_request_result` 가 `OrderResult` → `Order` 로 3 필드 propagate.
- 기존 필드/검증/상태 일관성 검사 변경 zero.

### 2.3 마이그레이션 전략 ("no Alembic" 유지)

- **신규 DB**: `db.py` orders DDL 이 3 컬럼 보유 → fresh DB 는 마이그레이션 불요.
- **기존 DB**: 수동 `scripts/migrate_0019_add_order_cost_fields.py` —
  - **백업 먼저**: 마이그레이션 전 DB 파일을 `<db>.bak.<UTC timestamp>` 로 복사 (shutil). 백업 실패 시 중단(마이그레이션 안 함).
  - **idempotent**: `PRAGMA table_info(orders)` 검사 후 없는 컬럼만 `ALTER TABLE orders ADD COLUMN <name> TEXT`. 이미 있으면 skip, 재실행 무해.
  - **검증**: 마이그레이션 후 PRAGMA 로 3 컬럼 존재 확인, 없으면 에러 (exit 1).
  - **rollback**: `--rollback <backup>` 시 SQLite DROP COLUMN 제약 회피 — 파일 복원 방식 (현 DB 를 `<db>.pre-rollback.<UTC timestamp>` 백업 후 백업 복원).
  - 명확한 stdout 상태 출력(백업 경로/추가 컬럼/검증 결과). 침묵 금지(CLAUDE.md §6.3).

### 2.4 domain-additive 허용 (D13 invariant 정합)

build-phase(Stage 0–7) 동안 도메인 모델 **additive 확장**(`OrderResult.tax/commission/broker_org_no`)은 ADR 0019 하 허용. ADR 0012 §1.6 #6 의 "변경 zero invariant" = Stage 8 운영 윈도우 룰 — build 동안 additive 확장은 별개. **Port 시그니처 불변** (BrokerPort / OrderRepoPort 변경 zero).

---

## 3. Drivers

- 실머니 주문 스키마 — 첫 실거래 체결 전 비용/라우팅 컬럼 부재 = 잔고 불일치 risk (BLOCKING).
- cancel 라우팅(`KRX_FWDG_ORD_ORGNO`)이 schema-level 필드 없이는 불가능 (ADR 0020 §2.2).
- "no Alembic" 단순성 유지 (CLAUDE.md §10.3 / ADR 0012 §1) — 수동 스크립트 + 백업/rollback.
- 실머니 마이그레이션 = 되돌릴 수 있어야 함 (백업/rollback 필수, ADR 0012 D17).

---

## 4. Alternatives Considered

1. **JSON blob 컬럼 1개** (`cost_json`) — 거부. Decimal/TEXT 컬럼 패턴(CLAUDE.md §2) 위반 + 쿼리/검증 어려움.
2. **tax/commission 통합 단일 `fees` 컬럼** — 거부. ADR 0012 D17 이 거래세/수수료 분리 명시. KIS 가 향후 per-order 분리 제공 시 분리 컬럼이 흡수 가능.
3. **NOT NULL + 0 default** — 거부. 기존 행 호환성 깨짐 + provisional(KIS 미제공) 상태를 0 으로 위장 → None(미측정) 과 0(측정값) 구분 불가 (CLAUDE.md §6.3 정신).
4. **Alembic 도입** — 거부. 단일 additive 마이그레이션에 과한 의존성(CLAUDE.md §0.3 외부 의존성 승인) + "no Alembic" 정책 변경.

---

## 5. Why (선택 근거)

nullable Decimal/str 컬럼 + 수동 idempotent ALTER 는: (a) 기존 행/코드 회귀 zero, (b) provisional(None) 과 측정값 구분 보존, (c) "no Alembic" 단순성 유지, (d) 백업/rollback 으로 실머니 안전성 충족. ADR 0020 §4 의 "per-order 비용 미제공" 현실을 None 으로 정직하게 표현하면서 Stage 7 실응답 검증 후 값 채우기 path 를 열어둔다.

---

## 6. Consequences

**Positive**:
- write (Stage 5) 가 존재하는 컬럼을 소비 — BLOCKING-1 해소.
- cancel 라우팅 schema-ready (`broker_org_no`).
- 기존 1954 tests 회귀 zero (additive nullable).
- 마이그레이션 idempotent + 백업 + rollback → 실머니 안전.

**Negative / 보류**:
- tax/commission 값은 당분간 None (provisional) — 실비용 회계는 Stage 7 후속.
- SQLite rollback = 파일 복원 (DROP COLUMN 미지원) — 마이그레이션 이후 추가된 데이터는 rollback 시 손실. 운영 절차로 완화 (Stage 5 진입 전 1회성 마이그레이션).

---

## 7. Follow-ups

1. **Stage 5 (write)** — order-cash 응답에서 `KRX_FWDG_ORD_ORGNO` → `broker_org_no` 캡처. cancel(order-rvsecncl) 라우팅에 사용.
2. **Stage 7 (모의투자 실응답)** — per-fill tax/commission attribution 검증 후 값 채우기 로직 결정 (ADR 0020 §4 provisional 해소). R9 (거래세/수수료 정확) 영향.
3. **운영** — 기존 운영 DB 존재 시 Stage 5 진입 전 `scripts/migrate_0019_add_order_cost_fields.py --db <path>` 1회 실행 + 백업 보존 확인.
