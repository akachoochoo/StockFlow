## 2. KIS API 스펙 (공식 GitHub 1차 출처 — Stage 2.1 어댑터 설계 정본, 실응답 검증 대기)

### 2.1 도메인 + 인증
- 실거래 `https://openapi.koreainvestment.com:9443` / 모의투자 `https://openapivts.koreainvestment.com:29443`.
- OAuth2: `POST /oauth2/tokenP` (body `grant_type=client_credentials` + `appkey` + `appsecret`) → `access_token` / `access_token_token_expired` ("YYYY-MM-DD HH:MM:SS") / `token_type`=Bearer. **TTL 24h** (만료 6h 이내 재발급 시 동일 토큰 반환).
- 공통 헤더: `authorization: Bearer <token>` + `appkey` + `appsecret` + `tr_id` + `custtype`(P) + `tr_cont`.
- **TR_ID 실→모의 변환**: 첫 글자 `T/J/C` → `V` (예 `TTTC8434R`→`VTTC8434R`). `F...` (시세) = 실/모의 동일.
- hashkey (`POST /uapi/hashkey`) = 선택 (현재 필수 아님).

### 2.2 엔드포인트 + 핵심 응답 필드 (전부 string → `Decimal(str(v))`, float 경유 금지)

| 용도 | 엔드포인트 | TR_ID (실 / 모의) | 핵심 필드 |
|---|---|---|---|
| 잔고/포지션 | `GET /uapi/domestic-stock/v1/trading/inquire-balance` | `TTTC8434R` / `VTTC8434R` | `output1[]`: `pdno`/`hldg_qty`/`ord_psbl_qty`/`pchs_avg_pric`/`prpr`/`evlu_pfls_amt`/`evlu_pfls_rt`. `output2[]`: `dnca_tot_amt`(예수금)/`tot_evlu_amt`/`thdt_tlex_amt`(당일 제비용). 모의 20건/실 50건 페이지네이션 |

| 미체결 활성주문 | `GET .../inquire-psbl-rvsecncl` | `TTTC0084R` / 모의 미확인 (실증) | `odno`/`ord_qty`/`tot_ccld_qty`/`psbl_qty` |

### 2.3 운영 특성
- **Rate limit**: 실 20/s, **모의 2/s** → 초과 시 `EGW00201` (유량 초과). 어댑터 throttle 필수 (모의 0.5s sleep).
- **응답 공통**: `rt_cd`("0"=성공) / `msg_cd` / `msg1`. 토큰 만료 = `rt_cd != "0"` + 토큰 관련 `msg_cd`.

## 3. Open Q 1~4 결정

### Open Q 1 — KIS 종목 코드 형식 → **6자리 숫자 문자열 (해소)**
`pdno` / `PDNO` / `FID_INPUT_ISCD` = 6자리 숫자 문자열 (069500, 132030 그대로; ETN만 `Q`+6자리 = 해당 없음). 도메인 `Asset.code` → KIS PDNO 직접 매핑. 최종 확인 = 모의투자 응답 (Stage 4).

### Open Q 2 — 모의투자 partial fill 시뮬 여부 → **실증 보류 (Stage 7) + D5(a) 차단 유지**
KIS 는 `tot_ccld_qty` / `rmn_qty` 로 부분체결 보고 (`tot_ccld_qty < ord_qty` → 미체결 잔량 유지). **모의투자(VTS) 시뮬 여부는 공식 문서 미확인 → 모의투자 5영업일 실증** (D6 iv-b, Stage 7; 실증법 = 호가 밖 지정가 → `VTTC0081R` 조회로 `tot_ccld_qty < ord_qty` 관찰). 시뮬 여부와 무관하게 **D5(a) 차단 정책 유지** (부분체결 ≠ 차수, 100% 체결 시만 `split_level++`, CLAUDE.md §4.4 / ADR 0002 §3 정신).

### Open Q 3 — pykrx vs KIS 데이터 불일치 시 정본 → **KIS 정본 + pykrx fallback (해소)**
KIS `inquire-daily-itemchartprice` (FHKST03010100) 수정주가 일봉 제공 확인 → **실거래 의사결정 = KIS 정본**, pykrx = fallback (ADR 0012 D1 c-read / D20 default 정합). 불일치 감지 시 KIS 우선.

### Open Q 4 — G2 "무사고" 해석 → **운영/무결성 사고만 (사용자 결정 2026-05-22, Option A)**

"무사고"(no-incident) = 다음 운영/무결성 사고가 **zero** (G2.1~G2.3 capital escalation 200→300→500 + D6 paper→실거래 전환 + D19 rollback trigger 기준):

1. Reconciliation mismatch (DB vs KIS 잔고 불일치)
2. 계획되지 않은 hard halt / kill switch 발화
3. 주문 오류 (의도와 다른 종목 / 수량 / 가격) 또는 중복 주문
4. Decision 동일성 projection 위반 (백테스트 vs 라이브, ADR 0012 §2.3 B2)
5. 미처리 예외 / 시스템 크래시
6. 텔레그램 알림 누락 (발송 N ≠ 수신 N)
7. NTP 동기화 실패 상태에서의 거래

**명시 제외 (사고 아님)**: P&L 손실 / 단일 종목 -20% 손절 발동 (D2 b' 안전장치 *정상 작동*) / 정상 시장 변동. **근거**: Phase 1.1 본질 = **시스템 정확성 검증** (수익성 검증 아님 — 그건 backtest 영역). 손실을 사고로 보면 시장 리스크와 시스템 리스크를 혼동하여 capital escalation 을 부당 차단함. CLAUDE.md preamble "동작하는 것 같다 ≠ 안전하다" 의 *안전 = 정확성* 해석 정합.

## 4. 부수 발견 + 다른 ADR 영향

- **idempotency**: KIS 는 클라이언트 idempotency key **미지원** → 내부 UUID (`OrderRequest.idempotency_key`) 발급 + 응답 `ODNO` 매핑 저장 + `inquire-daily-ccld` 조회로 중복 방지 (CLAUDE.md §4.1 / §4.3, Stage 2.5 / 5 핵심 설계).
- **token 24h TTL**: 매 cron 진입 시 `get_balance` (read-only) 호출로 토큰 사전검증 (ADR 0012 D1 / §1.10 시나리오 E). 만료 시 주문 진입 전 재발급 또는 halt.
- ⚠️ **tax/commission (ADR 0019 영향)**: 기본 주문 (`order-cash`) / 잔고 응답에 **per-order 세금·수수료 직접 없음** (계좌요약 `thdt_tlex_amt` = 당일 제비용 *총액*만). → **ADR 0019 컬럼 형태 provisional 재확인** — `OrderResult.tax`/`commission` per-fill 귀속은 실증 필요 (Stage 4.5 schema 확정 + Stage 7 모의투자 실응답). R9 (거래세/수수료 정확) 영향.

## 5. 실응답 검증 보류 (계정 발급 후 — Stage 4 / 7)

본 ADR 은 공개 문서 기반. 다음은 실 KIS Mock / 모의투자 응답으로 검증 후 정정 박제:
1. 전 endpoint 실응답 Pydantic strict parse (Stage 4 paper-1, §1.6 #4-b).
2. 모의투자 partial fill 시뮬 동작 (Open Q 2, Stage 7).
3. per-fill tax / commission attribution (ADR 0019, Stage 4.5 / 7).
4. `inquire-psbl-rvsecncl` 모의 TR_ID + 신형(`TTTC0012U`) vs 구형(`TTTC0802U`) order TR_ID 현행 동작.
5. EGW 에러코드 전체 목록 + 토큰만료 `msg_cd`.

### 5.1 검증 진척 박제 (2026-05-23, `trading kis-check` 실서버)

**read 표면 = LIVE 실서버(`openapi.koreainvestment.com:9443`, `KIS_TRADING_MODE=real`) 실응답 검증 통과** (`trading kis-check`, read-only — 주문 코드 부재, 돈 이동 zero):
- OAuth2 token 발급(`/oauth2/tokenP`) ✅ — appkey/appsecret/IP 유효 확인.
- `get_balance`(inquire-balance, `TTTC8434R`, output2 `dnca_tot_amt` parse) ✅ — 예수금 850,028 KRW.
- `get_holdings`(output1[] parse) ✅ — **empty(0종목) 케이스만** 확인(non-empty 미확인).
- `get_price`(inquire-price `FHKST01010100`, output `stck_prpr` parse + ±30% 이상치 가드 통과) ✅ — 069500 = 123,350 KRW.
- KISClient(공통헤더 / throttle / rt_cd 검증) + KISConfig.from_env(real) + KISAuth(TTL 캐시) 라이브 동작 확인.

**잔여 (위 §5 목록 중 미해소)**: §5.1 은 §5(1)의 read 표면 부분 충족. **미확인**: get_ohlcv(itemchartprice) 실응답 / get_holdings non-empty / 모의투자(VTS) 서버 검증(paper 계정 OPSQ2000 미해결 — D6 paper 게이트 별도 필요) / §5(2)(3)(4)(5) write·partial·tax·취소·에러코드. 디버깅 중 부수 fix 2건: 토큰 403 OAuth `error_description` surface (`auth.py`) + KISApiError `msg1` 한글 사유 surface (`_client.py`).

**경계 재확인**: 본 검증은 실계좌 **read-only**(잔고/시세 조회). 실거래 **주문** ON 은 여전히 D16 게이트(D6 paper trading 10영업일 무사고 + NTP + 5조건) 뒤이며, write 코드는 미작성(Stage 5). paper-before-real-**trading** 원칙(ADR 0012 D6/D16) 불변.

## 6. Consequences / Follow-ups

- **Stage 2.1** (KIS Pydantic models) 설계 정본 = §2.2 표 (Balance/Position/OrderResult/OHLCV, 전부 string→Decimal).
- **Stage 2.5** (PENDING-recovery) = `inquire-daily-ccld` (`tot_ccld_qty`/`rmn_qty`) — 자동 catch-up 금지, 사람 명시 재시작.
- **Stage 5** (write) = `order-cash` (지정가 `ORD_DVSN=00`) + cancel `order-rvsecncl` (`ORGN_ODNO` + `KRX_FWDG_ORD_ORGNO`). idempotency = 내부 UUID + ODNO.
- **어댑터 throttle**: 모의 2/s / 실 20/s, `EGW00201` 시 backoff (단 자동 무한재시도 금지 — §1.6 #1, 반복 실패 시 halt).
- **ADR 0012 D20** → 본 ADR 0020 으로 해소.
- **CLAUDE.md §16.4 트리거 6** (모의투자→실거래 전환 게이트) "무사고" 해석 = 본 ADR §3 Open Q 4.
