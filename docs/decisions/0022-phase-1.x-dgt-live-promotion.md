## 1. Context

사용자가 연구용 DGT 의 성적을 근거로 **실거래 적용**을 희망. 결정 라운드 입력 (2026-05-23 인터랙티브):

- **역할 = MDD 방어·횡보 수확** (절대 수익 추구 아님). 강세장에서 B&H 미달은 **수용**. → 연구 결론(ADR 0014 "MDD 방어 전용" / ADR 0018 regime-split)과 정합. 이 합의가 본 ADR 의 전제.
- **진행 = 결정 라운드 + ADR 부터** (구현 선행 금지).

현 상태:
- DGT 는 5th ring research overlay. inner ring (`domain/use_cases/cli/...`) 의 `from src.research.*` **FORBIDDEN** → 실거래 경로 배선 불가.
- DGT 최적 구성(memory `dgt-optimal-config`) = **일봉 daily-rebalance + ADR 변동성 + Volume Gate**, `src/research/dgt/{adaptive_runner,paper_adaptive_runner}.py`.
- Phase 1.1 실거래 인프라 머지(PR #1)됨. 단 **live 미활성** (Stage 8-7 사람 게이트) — 기존 `PriceDropStrategy` 조차 실돈 운용 전.
- 라이브 실행 모델 = cron 1일 1회, 종가 지정가, 단일 프로세스 (§10.1). → **일봉 daily-rebalance DGT 는 호환**, 분봉 DGT 는 장중 인프라 부재로 **불가**.

## 3. Drivers

- 사용자 의지 + 연구 축적 (ADR 0007~0018, 1728+ DGT tests). 단 역할이 "MDD 방어"로 한정되어 연구 결론과 모순 없음.

## 4. Alternatives Considered

1. **DGT 신호만 5th ring 유지 + 사람이 수동 주문** — 자동매매 목적 미달. 단 paper 단계 전 "신호 관찰" 용도로는 유효(중간 단계 후보).
2. **B&H 정적 보유 (DGT 안 씀)** — 연구상 강세장은 이게 우위. 그러나 MDD 방어 목적엔 부적합 (B&H MDD 27~34%).
3. **PriceDrop 유지 + 일부 종목만 DGT** — 종목별 전략 차등(ADR 0021 `allow_per_asset_params` 정합). D6 형태에 따라 가능 — §8 Q3 와 연동.
4. **분봉 DGT** — 거부(D3). 장중 인프라 부재 + §10.1 단일 cron.

## 5. Why (선택 근거 — 잠정)

역할을 "MDD 방어"로 한정하면 DGT 의 구조적 약점(강세장 B&H 미달)이 *수용된 trade-off* 가 되어 연구 결론과 정합한다. research→domain 승격은 §14 가 예고한 정식 경로이며, backtest↔paper 동일성 + paper-first 로 실돈 안전성을 확보한다. G4 불변 해제는 phase 본질 차이(연구 → production 진입)로 ADR 0012 §1.6 #6 의 선례(Phase 1 = production rings 진입)와 동형.

**Positive**:
- 횡보/하락장 자본 보존 도구 확보 (실증 시).

- 강세장 기회비용 (B&H 미달) — D2 로 수용했으나 운영 중 체감 가능.

### 9.0 도메인 규칙 위반 평가 = PASS
DGT 계산 코어(`adaptive_runner.py` / `paper_adaptive_runner.py` / `formulas.py` / `cost_model.py` / `state.py`)는 **외부 import zero / `datetime.now()`·`date.today()` zero(시점 = OHLCV.trade_date 주입) / Decimal-only / float zero**. 도메인 import 규칙(CLAUDE.md §1.1/§2/§3.2) 위반 없이 승격 가능. 유일한 변환 작업 = mutable dataclass state(`state.py:14`) → 도메인 frozen 모델 + ring 이동(5th → domain).

### 9.1 Q1 (승격 형태) → 권고 **B (신규 grid 패러다임 + 신규 GridSlot/GridState)**
- **근거**: 구조적 모델 불일치. `SplitSlot` = 평단 기준 고정수량 슬롯, SELL = 슬롯 entry 수량 정확 매도(`models.py:1052-1064`, `daily_orchestrator.py:567-579`). - 옵션 B = PriceDrop/ProfitTarget/SplitSlot/SupportSlot 0 변경(§14 보존 invariant 자동 충족, G1 회귀 zero 구조적 보장). dispatch 확장점 = `composition.py:77-106` `create_buy_strategy`/`slot_model_for_buy_strategy` 문자열 분기에 `"dgt"` 추가.

### 9.2 Q2 (그리드 매도 ↔ 손절) → 권고 **옵션 2 + profit_guard opt-in**
- **사실 정정**: 현 시스템에 자동 손절 없음. `StopLossPolicy`(`stop_loss.py:54-95`) = 순수 breach 감지기, live_runner는 **알림-only**(`live_runner.py:24-28,123-129`), 자동 매수차단조차 미구현.
- 손절은 그리드와 "통합"이 아니라 **알림 레이어로 공존**(§11.4 자동손절 금지 불변). 그리드가 SELL 전권 보유(ProfitTargetSell 미적용 — 같은 holdings 두 SELL 주체 경쟁 시 idempotency 충돌·이중매도). `profit_guard`(평단 이하 매도 억제, `state.py:28` avg_cost) opt-in 노출, 실돈 진입 시 기본 ON 권고.
- 우선순위: ① −20% breach → 알림 + (사람) 그리드 비활성 검토 ② 그리드 daily SELL은 profit_guard ON 시 `level_price > avg_cost`만 ③ 자동 매도 0.

### 9.3 Q3 (universe + 자본) → 권고 **저가 ETF 1종(069500) n=11 유지, 폴백 = n 축소(7~9)**
- 절삭 근원 = `paper_adaptive_runner.py:320` `(holdings/(n+1)).quantize(ROUND_DOWN)` → 고가주 1주 미만 = 0주 매도. 069500(~3.5만원)은 250만원으로도 매도 여력 충분.

- 자본 증액(종목당 2,500만원)은 ADR 0012 "소액" 합의 위반 → 최후순위.

### 9.4 신규 구조 충돌 (§8 에 추가 — 승격 전 필수 해소)
- **Q6 (HIGH) Orchestrator 통합**: `DailyOrchestrator`는 하루 0..1 BuyAction 가정 + Decision invariant 3(`buy_slot ∉ sell_slots`, `models.py:1398-1406`). 그리드는 한 bar 다수 레벨 동시 buy+sell(`paper_adaptive_runner.py:200-226`). → 그리드를 orchestrator **통합 vs 별도 use_case 우회** 결정 필요(G1 핵심 분기).
- **Q7 (HIGH, §4.1) idempotency_key 스킴**: 현 키 = `{fqn}:{date}:{side}:{slot_number}`(`daily_orchestrator.py:883-906`). 그리드는 하루 같은 side 다수 거래 → slot_number 키 충돌. 그리드용 키(예: `...:grid:{level_idx}`) **신설 필수**.
- **Q8 (MEDIUM, §4.2/§4.4/G2) 종가 다중 지정가 + partial fill 동일성**: backtest는 종가 교차 판정(`prev_close < level <= curr_close`) + full fill 가정(ROUND_DOWN). 실거래는 종가 1회 cron(§10.1)에 다수 지정가 동시 제출 + KIS partial fill 가능(§4.4 차단) → 체결이 backtest와 어긋나 G2(동일성) 위협. 체결 모델 정합 방안 필요.

차트가 초기 그리드만 정적으로 그려 on_breach 재중심이 안 보이던 문제 해결.
**방법 A**(GridRunner 가 바별 활성 그리드 기록): `GridDailyValue.grid_levels`
(그날 거래에 적용된 그리드, 리셋 전) 추가 → `build_dgt_chart_html` 가 research
`_serialize_grid_series` 로 **시변 LineSeries**(grid_groups) 렌더 → 리셋마다 그리드가
계단식 이동. grid_levels 미기록 시 초기 그리드 정적 폴백. 기본값 `()` 이라 회귀
zero(research 동치/determinism 테스트는 (trade_date,total_value) 비교라 무영향).
검증: 095660 113바 전부 기록, 12회 리셋이 바닥 레벨 12개 값으로 반영.

### 11.10 게이트 억제 이벤트 시각화 (2026-05-25) — slope/volume gate 마커

차트가 게이트(slope/volume)에 막혀 *발생하지 않은* 거래를 표시하지 못해 "왜
이 봉에서 매도가 안 됐나"가 안 보이던 문제 해결 (사용자 발견: 095660 1/6 매도
부재 = +6.05% slope 발화). **표시 정책 = 억제된 거래만**(사용자 확정): 게이트가
매일 활성이어도 ① 교차가 있고 ② 보유분/현금이 있어 가정 거래가 실제로 emit
되었을 때만 마커 — gate-활성 전체 표시(노이즈)는 기각. **대상 = slope + volume
둘 다**(동일 메커니즘).

구현 (cost-free 전략 → use_case → 렌더러, inner→outer):
- `GridStrategy`(domain): `_slope_gate`/`_volume_gate` 가 magnitude(roc/ratio)
  반환, `GridEvaluation.gate_skips: list[GridGateSkip]` 추가(side+level_prices+
  reasoning{gate,slope_roc,volume_ratio}). 가정 거래 판정은 기존
  `_sell_decision`/`_buy_decision` 재사용(게이트로 hold/cash 미진화 → 원본 기준).
- `GridRunner`(use_case): `ev.gate_skips` 에 trade_date 부착 →
  `GridRunResult.gate_events: list[GridGateEvent]`.
- `build_dgt_chart_html`(scripts): `_gate_markers` 가 회색 ⊘ 마커 그룹 추가 →
  마커 그룹 2개 → 렌더러가 토글 체크박스 자동 표시(`_interactive_chart` 기존
  멀티그룹 인프라 — 코어 0변경). SELL 억제=aboveBar, BUY 억제=belowBar.

기본값 `[]`/`()` → 회귀 zero (동치/determinism/profit_guard 테스트 전부 trades+
cash+holdings 비교라 무영향). 검증: 095660 16개 억제 이벤트, 1/6 = `⊘S slope
+6.0%`(levels 25,398/25,906, slope_roc 0.0605). 신규 11 tests(grid 7 + runner 2
+ pipeline 2), full suite green, ruff/mypy/namespace clean.

### 11.11 수익 로그 실현/미실현 분해 (2026-05-25)

수익 로그가 총수익률만 보여 "확정 수익(실현)"과 "보유분 평가손익(미실현)"이 안
구분되던 문제 해결 (사용자 요청). DGT 는 횡보 수확형이라 이 분해가 특히 유의미 —
095660 사례: **실현 +4,547,070(+4.55%)** vs **미실현 −11,289,256(−11.29%)** =
총 −6.74%. 그리드가 확정 수익을 쌓는 동안 보유분은 평단 이하(§11.9 slope-gate
보유 연장과 정합).

구현:
- `GridRunResult.pnl_split() -> (실현, 미실현)` (use_case). 실현 = Σ(순매도대금 −
  매도분 평균원가, 평균원가법). **미실현 = 잔차**(반올림 총손익 − 반올림 실현).
- **정수 원 반올림**(ROUND_HALF_UP): KRW 불가분 + 평균원가 나눗셈의 Decimal
  28-sig-fig 반올림이 `==` 항등식을 깨던 문제 제거(잔차 산출 단독으론 재가산 시
  여전히 깨짐 — 실데이터로 발견). 합산 항등식 정확 보장(불변 테스트).
- CLI 출력: `grid-backtest` 단일/멀티 양쪽 text(`├ 실현 / └ 미실현`) + `--json`
  (`realized_pnl`/`unrealized_pnl`, 멀티는 per_asset 도). `backtest --config` 자동
  라우팅 경로(run_backtest 파이프라인)가 멀티 경로라 사용자 로그에 즉시 반영.

신규 5 tests(runner 4 + CLI 4 assert 보강), full suite green, ruff/mypy/namespace
clean. (별건 발견: `main.py:626/633` `sorted(str|None)` mypy 경고 = 본 작업 무관
선존 — 미수정.)

### 11.12 극단 가중 (extreme weighting) — INVALIDATE (2026-05-25)

**가설** (사용자 제안): 그리드 최상단 가까울수록 매도 수량↑ / 최하단 가까울수록
매수 수량↑ 로 가중하면 횡보 수확을 강화할 수 있는가?

**설계 확정** (사용자 인터뷰 4축): ① 선형 `w = 1 + s·pos` (SELL: i/n / BUY:
(n-i)/n) ② steepness `s` (기본 off=0) ③ 총량 보존 = Approach A (`floor((hold×w)/
(n+1))`, 곱 먼저·나눗셈 나중 → s=0 비트 동치) ④ 윈도 상대 + **buy-damping**
(slope_roc<0 면 매수 측 s→0, 저점 피라미딩 차단). opt-in 플래그(기본 off → 회귀
zero).

**사전 등록 게이트**: 횡보 수확 개선 ≥ base AND 하락장 MDD ≤ hard stop.

**백테스트** (OFF vs ON s=1, slope_gate 동일, on_breach):

| 레짐 | 종목 (B&H) | Δ수익(ON−OFF) | ΔMDD |
|------|-----------|--------------|------|
| 강세 | 005930 (+37%) | −8.4%p | −0.3 |
| 강세 | 005380 (+86%) | −4.6%p | +2.1 |
| 강세 | 132030 (+69%) | −10.9%p | −0.8 |
| 강세 | 069500 COVID(+122%) | −6.6%p | +0.5 |
| 약보합 | 055550 (+21%) | −2.5%p | +3.5 |
| **횡보** | 069500 flat(0.6%) | **−2.0%p** | −0.2 |
| 하락 | 069500 (−23%) | +0.1%p | +0.2 |
| **하락** | 095660 (−25%, 실제config) | **+2.3%p** | **+2.0** |

steepness↑(s=2) → 모든 레짐 단조 악화.

**판정 = INVALIDATE** (게이트 FAIL — 횡보 −2.0%p 로 핵심 가설 반증). 상승·약보합·
횡보 전부 수익 악화(천장 대량 매도가 랠리 조기 이탈 + 횡보선 역선택 노출). 유일한
이득은 **깊은 하락장 방어**(095660 +2.3%p/MDD +2.0%p)인데 이는 이미 profit_guard·
slope_gate 담당 영역. ADR 0014 H3(비대칭 grid MDD breach)·D4(on-breach 하락 확대)
무효화 계보와 정합. **코드 revert**(inner ring 청결) — 본 §11.12 가 정본, 재시도
시 근거. 무효화 카탈로그 추가: "극단 수량 가중 (X) — 상승/횡보 수익 악화, 하락만
근소 이득".
