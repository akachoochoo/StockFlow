### 1.2 학습 목표 명확화 (사용자 §2.1 박제)

#### 1.2.1 패러다임 비교 (가치 → 기술적)

Phase 0.8 의 핵심 = **매수 패러다임 차원 변경**:

| 차원 | Phase 0 / 0.5 / 0.7 | Phase 0.8 |
|---|---|---|
| 매수 트리거 | `PriceDropStrategy` — `avg_price` 대비 N% 하락 (가치) | `SupportLevelStrategy` — 보조 지표 기반 지지선 도달 (기술적) |
| 의사결정 변수 | 평균 단가 + 현재가 + 임계값 | 가격 + MA / BB / RSI 등 보조 지표 |
| 슬롯 의미 | 차수 번호 (1~7, 누적) | 지지선 종류 (1~7, 매핑) |
| 박영옥 원전 정신 | 가치 투자 (분할 매수) | 기술적 분석 (지지선) |

#### 1.2.2 박영옥 원전 정신 폐기 아님

`PriceDropStrategy` (Phase 0~0.7) 는 박영옥 세븐스플릿의 핵심 정신
(분할 매수 + 평단 관리). **Phase 0.8 = 폐기 아닌 비교** — 두 패러다임
모두 유지:

- yaml `buy_strategy: "price_drop"` → 기존 strategy
- yaml `buy_strategy: "support_level"` → Phase 0.8 신규 strategy
- 둘 다 회귀 invariant 보존 (`PriceDropStrategy` 변경 zero)

→ Phase 0.7.3 baseline (PriceDropStrategy) 와 Phase 0.8 (SupportLevelStrategy)
는 같은 환경 (자산 + 자본 배분 + 매도 + 재진입) 에서 매수 패러다임만
변경한 직접 비교.

### 1.3 결정 1 = (B-1) — SupportSlot 신설 (한 종목 한 전략)

| 옵션 | 채택 | 근거 |
|---|---|---|
| A) `slot_number` 의미 다양화 (기존 `SplitSlot` 재사용) | 거부 | 의미 혼란 — 차수 번호 vs 지지선 종류 동시 |
| **B-1) `SupportSlot` 신설 (한 종목 한 전략 가정)** | **채택** | 의미 명확. yaml 의 `buy_strategy` 가 자산별 결정 → 자산은 한 가지 슬롯 모델만 사용 |
| B-2) `SupportSlot` 신설 + 자산이 두 슬롯 모델 동시 보유 | 거부 | 복잡성 ↑ — Phase 0.8 본질 (패러다임 비교) 와 다른 차원 |
| C) 슬롯 없는 전략 (단일 슬롯) | 거부 | 7-split 정신 (분할 매수 / 매도) 약화 |

채택 효과 — 도메인 모델:
- `SupportSlot` 신규 — `slot_number` (1~7) = 지지선 종류 매핑 (§1.6.1)
- `Position` 의 `slots` 필드 = `list[SplitSlot] | list[SupportSlot]`
  union (자산이 한 가지 슬롯 모델만 보유)
- `AssetContext` 의 strategy 가 슬롯 모델 결정 — 동일 자산 yaml 변경
  시 명시적 마이그레이션 필요 (Phase 0.8 동안은 zero)
